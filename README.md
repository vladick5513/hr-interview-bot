# hr-interview-bot

Прототип Telegram-бота для объективной оценки кандидатов. Бот переводит вакансию
в измеримые критерии hard skills, проводит с кандидатом техническое интервью в чате,
оценивает каждый ответ по критериям и присылает рекрутеру отчёт со скорингом.

## Быстрый старт

1. Создать бота у [@BotFather](https://t.me/BotFather) и получить токен.
2. Скопировать `.env.example` в `.env` и заполнить:

   | Переменная | Что указать |
   |---|---|
   | `BOT_TOKEN` | токен от @BotFather |
   | `HR_IDS` | Telegram id рекрутеров JSON-списком: `[123456789]` или `[111,222]`. Узнать свой id — [@userinfobot](https://t.me/userinfobot) |
   | `OPENAI_API_KEY`, `OPENAI_MODEL` | ключ и модель OpenAI с поддержкой structured output |
   | `DB_USER`, `DB_PASS` | любые: Postgres в Docker создастся с ними |
   | `HH_*` | можно не заполнять, пока нет приложения hh (см. «Подключение hh.ru») |

3. Запустить: `docker compose up --build -d`. Миграции применяются при старте бота.
4. Каждый рекрутер из `HR_IDS` пишет боту `/start`: без этого бот не сможет присылать
   ему отчёты.

Первое интервью в Telegram:

1. `/vacancy` → файл `.txt` с текстом вакансии → «Сгенерировать» → проверить черновик
   критериев и вопросов → «Сохранить».
2. `/new` → выбрать вакансию → файл `.txt` с резюме. Бот пришлёт выжимку резюме
   и ссылку для кандидата.
3. Открыть ссылку (можно самому) и пройти интервью. После последнего ответа рекрутеру
   придут итог и HTML-отчёт.

Логи: `docker compose logs -f bot`. Остановить: `docker compose down` (данные сохранятся).

## Команды бота

| Команда | Кто | Что делает |
|---|---|---|
| `/start`, `/help` | рекрутер | список команд |
| `/vacancy` | рекрутер | завести вакансию: критерии и обязательные вопросы |
| `/new` | рекрутер | создать интервью по резюме и получить ссылку для кандидата |
| `/connect_hh` | рекрутер | подключить аккаунт работодателя hh.ru |
| `/track` | рекрутер | отслеживать новые отклики на вакансию hh.ru |
| `/responses` | рекрутер | рейтинг откликов по вакансии |
| `/invite_<id>` | рекрутер | пригласить кандидата из рейтинга на интервью |
| ссылка `t.me/<бот>?start=…` | кандидат | начать интервью |

## Как работает

### Вакансия → профиль для интервью

1. Рекрутер присылает ссылку на вакансию hh.ru (нужен подключённый hh) или файл `.txt`.
   Длинный текст сообщением не принимается: Telegram разбивает его на части.
2. Выбирает, откуда брать обязательные вопросы:
   - «Сгенерировать» — вопросы составляет LLM;
   - «Только свои» — заготовленный пул вопросов компании;
   - «Свои + дополнить» — пул компании, а к must-have критериям без вопросов LLM
     добавляет свои.

   Пул присылается одним или несколькими сообщениями (вопрос на строку) или файлом
   `.txt`, в конце — «Готово».
3. LLM составляет 4–6 измеримых критериев hard skills (что проверяем, вес 1–3,
   must-have) и привязывает вопросы к критериям. Вопросы компании не переписываются:
   LLM возвращает только их номера, текст берётся из пула дословно.
4. Бот показывает черновик: источник каждого вопроса и вопросы компании, не подошедшие
   ни к одному критерию. Рекрутер пишет замечания, и LLM переделывает профиль,
   или нажимает «Сохранить».

### Интервью

1. Рекрутер в `/new` присылает резюме: ссылку на отклик hh.ru (`hh.ru/resume/…?t=<id>`),
   ID отклика или файл `.txt`.
2. LLM оценивает соответствие резюме каждому критерию (0–5 с обоснованием) и готовит
   3 вопроса по резюме. Они идут сначала к критериям без обязательного вопроса, чтобы
   проверить весь профиль, и опираются на заявления из резюме по этому критерию.
3. Кандидат отвечает текстом. Если ответ общий или не про критерий, бот задаёт один
   уточняющий вопрос.
4. Каждый ответ LLM оценивает по шкале 0–5 именно по критерию: подробный ответ не по теме
   получает не выше 1. В оценке — обоснование, короткая дословная цитата из ответа
   и расхождение с резюме, если оно нашлось.
5. Рекрутер получает итог в чат и HTML-отчёт: таблица критериев со ссылками на вопросы,
   все ответы, баллы, обоснования и цитаты.

### Скоринг

Итог считает код, а не LLM: формулу можно пересчитать руками (`app/services/scoring.py`).

- Балл критерия — среднее баллов его вопросов (0–5).
- Итог — взвешенное среднее по проверенным критериям в шкале 0–100. Сколько критериев
  проверено, видно в отчёте: «Проверено критериев: N из M».
- Вердикт: любой must-have ниже 3 — «не рекомендован». Иначе от 75 — «рекомендован»,
  от 50 — «на усмотрение», ниже — «не рекомендован». Непроверенный must-have не даёт
  рекомендовать: решение остаётся за рекрутером.
- Соответствие резюме выводится рядом для сравнения и в итог не входит.

Контроль галлюцинаций: код проверяет, что цитата действительно есть в ответе кандидата,
иначе в отчёте пометка ⚠. Резюме, вакансия и ответы передаются в промпт как данные,
а не инструкции.

## Подключение hh.ru

Отклики работодателя доступны только с токеном пользователя-работодателя, его выдаёт
OAuth hh.ru.

1. Зарегистрировать приложение на [dev.hh.ru](https://dev.hh.ru/admin), регистрация
   проходит модерацию. В настройках указать redirect URI, например
   `https://<домен>/hh/callback`.
2. Заполнить в `.env` `HH_CLIENT_ID`, `HH_CLIENT_SECRET`, `HH_REDIRECT_URI` (тот же адрес)
   и `HH_USER_AGENT` (название приложения и контактная почта, этого требует hh).
3. Бот слушает порт 8080 (OAuth callback и вебхуки). `HH_REDIRECT_URI` должен вести на него:
   на сервере через домен и reverse proxy, локально через туннель
   (`cloudflared tunnel --url http://localhost:8080` или ngrok).
4. Рекрутер пишет `/connect_hh`, входит в hh.ru как работодатель и разрешает доступ.
   Бот меняет `code` на пару токенов (с PKCE) и хранит её в `hh_tokens` отдельно для
   каждого рекрутера. Истёкший `access_token` бот обновляет сам.

### Автоматический скрининг откликов

1. `/track` → вакансия → ссылка на неё на hh.ru. Для вакансии, созданной по ссылке hh,
   отслеживание включается само. Бот подписывает рекрутера на вебхук hh о новых
   откликах. Отклики забираются токеном этого рекрутера, ему же приходят уведомления.
2. На новый отклик hh присылает вебхук. Бот ставит отклик в очередь (`hh_responses`)
   и сразу отвечает: hh ждёт ответа не дольше 5 секунд.
3. Фоновый воркер разбирает резюме и считает его балл 0–100 по весам критериев.
   Временные сбои (hh 429/5xx, LLM) повторяются до 3 раз. Очередь в БД, поэтому после
   рестарта необработанные отклики не теряются.
4. Рекрутеру приходит отклик с оценкой резюме и кнопками «Пригласить на интервью»
   (без повторного вызова LLM) и «Отклонить» (только у нас, на hh статус не меняется).

## Разработка

Без Docker нужны Python 3.12+ и PostgreSQL:

```bash
pip install -r requirements-dev.txt
alembic upgrade head
python -m app.main
```

Тесты (SQLite in-memory и локальный aiohttp-сервер вместо hh, без внешних сервисов) и линтер:

```bash
pytest
ruff check app tests && ruff format --check app tests
```

`OPENAI_BASE_URL` переключает бота на OpenAI-совместимый сервер в своём контуре
(vLLM, Ollama). Модель должна поддерживать structured output.

```
app/
├── vacancy/     # вакансии: модели, DAO, Telegram-роутер профиля вакансии
├── interview/   # интервью: модели, DAO, Telegram-роутер рекрутера и кандидата
├── hh/          # hh.ru: клиент API, OAuth, вебхуки, воркер скрининга, команды
├── llm/         # клиент OpenAI, промпты, схемы structured output
├── services/    # логика на несколько сущностей: интервью, скоринг, отчёт, скрининг
├── files.py     # чтение .txt из Telegram
└── migrations/  # Alembic
```

## Ограничения прототипа

- Интеграция с hh.ru написана по документации и покрыта тестами, но вживую не проверена:
  нужно зарегистрированное приложение.
- Бот работает в одном экземпляре. Черновики вакансий и незавершённые авторизации hh
  хранятся в памяти и теряются при рестарте.
- Токены hh хранятся в БД открытым текстом.
- Postgres берёт `DB_USER` и `DB_PASS` из `.env` только при первом создании базы. После их
  смены нужен `docker compose down -v` (данные удалятся) или смена пароля в самой базе.
- Сохранённую вакансию нельзя отредактировать, только завести заново.

## Бэклог

- Отправлять кандидату ссылку на интервью в чат отклика hh.ru
  (`POST /common/chats/{chat_id}/messages`, `chat_id` есть в отклике).
- Сверять отклики опросом `GET /negotiations/response?vacancy_id=…`: hh не гарантирует
  доставку вебхуков.
- Создавать интервью по отклику автоматически, без кнопки рекрутера.
- Шифровать токены hh, хранить черновики и OAuth-авторизации в БД или Redis.
- Редактирование и архивирование вакансий.
- Калибровка на экспертной разметке: согласованность с экспертами, precision/recall.
