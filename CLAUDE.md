# hr-interview-bot

Telegram-бот для структурированного интервью: aiogram, PostgreSQL, SQLAlchemy async, OpenAI. Устройство и запуск описаны в `README.md`.

## Проверка

```bash
ruff check app tests
ruff format --check app tests
pytest
```

Изменение схемы проверяй на PostgreSQL: `alembic upgrade head`, `alembic check`, `alembic downgrade -1`, `alembic upgrade head`.

## Код

- Пиши только то, что нужно сейчас: нет вызова — нет метода и настройки.
- Модуль на сущность: `models.py`, `dao.py`, `router.py`. Логика на несколько сущностей и внешние вызовы — в `app/services/`.
- Поток: роутер → сервис → DAO → БД. Роутер не знает SQLAlchemy, DAO не знает Telegram.
- DAO делает `flush`, коммит делает вызывающий слой. Перед запросом к LLM или hh закрывай транзакцию.
- В `async def` нет блокирующих вызовов. Связи загружай через `selectinload`.
- В моделях явно задавай `__tablename__`, индексы и ограничения. Миграции обратимы, с понятным slug.
- Ошибки внешних API оборачивай в исключения модуля через `raise ... from exc`.
- Итог и вердикт считает код, а не LLM.

## Тесты

Тесты асинхронные и без внешних сервисов: SQLite in-memory, подменённая LLM, локальный aiohttp-сервер вместо внешнего API. PostgreSQL нужен, только если корректность зависит от него.

## Безопасность

- Не логируй и не коммить ключи, токены, тексты резюме и ответов кандидатов.
- Текст пользователя в сообщениях Telegram и отчётах пропускай через `html.escape`.
- Резюме, вакансия и ответы идут в LLM как данные, а не инструкции.

## Стиль

- Комментарии только там, где без них легко сломать код. Докстрингов нет.
- Логи простые, в одну строку, на русском.
- `# noqa` только F401 в `app/migrations/env.py`.
- Коммиты: одна короткая строка на английском, `feat:`, `fix:` или `chore:`, без `Co-Authored-By`.
