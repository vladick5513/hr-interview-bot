Задача: $ARGUMENTS

Ты оркестратор. Код сам не пишешь. Слова агента «готово» не доказательство: основание — коды выхода команд и вердикт ревью. Агентам передавай пути к файлам, а не свой пересказ. Не делай merge в `main`.

Python и Ruff бери из `.venv` основной папки проекта. **Gate** — это:

```bash
ruff check app tests && ruff format --check app tests && python -m pytest -q
```

Остановись и спроси человека, если:
- задача пуста или неоднозначна, и от ответа зависит поведение;
- нужно изменить права доступа, удалить данные, сделать необратимую миграцию или работать с секретами, а задача этого прямо не требует;
- базовая ветка уже не проходит gate;
- после 3 кругов остаётся `blocker` или `major`.

## 1. Подготовка

1. Придумай короткий `<slug>` и выполни `git fetch origin`.
2. Создай отдельный worktree. Незакоммиченные изменения основной папки не трогай и не добавляй:
   ```bash
   git worktree add .agent-cycle/<slug>/wt -b agent/<slug> origin/main
   ```
3. Запиши исходную задачу и проверяемые критерии приёмки в `.agent-cycle/<slug>/task.md`.
4. Выполни gate в worktree.

## 2. Разработка

Запусти нового агента `developer` с путями к worktree и `task.md` и командами gate. Сам выполни gate. Если он падает, верни вывод разработчику. Добавляй в коммит только изменённые задачей файлы, без `git add -A`. Сообщение коммита пиши по `CLAUDE.md`.

## 3. Тестирование

Запусти нового агента `tester` с путями к worktree и `task.md`, без отчёта разработчика. Убедись, что изменён только `tests/`, и выполни gate.

Докажи, что тесты работают:
1. Создай временный worktree от `origin/main`, скопируй новые тесты и запусти их. Для новой функции они должны упасть.
2. Во временной копии текущей ветки обрати одно ключевое условие изменения и запусти тесты. Они должны упасть. Если не упали, верни тестировщику, чего не хватает.
3. Удали временные копии.

Для чистого рефакторинга первый пункт пропусти и укажи причину в отчёте. Если найдена ошибка приложения, верни её новому `developer` и повтори шаги 2–3. Сделай коммит тестов.

## 4. Ревью

Сохрани `git diff origin/main...HEAD` в `.agent-cycle/<slug>/diff.patch`. Запусти нового агента `reviewer` только с путями к `task.md`, `diff.patch` и worktree.

## 5. Цикл

- `CHANGES`: передай замечания новому `developer`, выполни gate и коммит, затем снова проведи проверку тестов, если изменилось поведение, и новое ревью.
- `PASS`: переходи к шагу 6.
- Разработчик может оспорить замечание доказательством. Решение принимает новое ревью или человек.

## 6. Передача человеку

1. Выполни gate. Если менялась схема, проверь миграции на PostgreSQL.
2. Запиши `.agent-cycle/<slug>/report.md`: задача, коммиты, критерии и чем проверены, результат gate и мутаций, число кругов, ревью, оставшиеся `minor`, что не проверено.
3. Покажи отчёт и попроси подтвердить публикацию. После подтверждения выполни `git push -u origin agent/<slug>`.
4. Если есть `gh`, открой PR с отчётом. Иначе дай ссылку `compare/main...agent/<slug>?expand=1`.
5. Напиши, что merge делает человек после зелёного CI. Удаляй worktree только после merge.
